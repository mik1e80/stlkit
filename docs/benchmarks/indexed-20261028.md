# IndexedMesh 100k 面转换对照（2026-10-28）

Windows NT 10.0.26200.0，32 个逻辑处理器，Native release；CPU 型号未采集。moon 0.1.20261023 (3778465)，moonc v0.10.17+d971670cd。自建 Apache-2.0 平面网格，250×200 单元、100,000 三角形、50,451 精确顶点，解析面积 50,000；开放平面不作为实体体积基准。没有使用外部下载模型。

`full` 生成 Mesh 并计算面积；`convert` 在同样生成 Mesh 后转换 IndexedMesh，比较面数、面积、包围盒和顶点数。每个模式独立进程，运行三次。转换路径包含构建原网格、去重哈希表、索引数据与一致性检查，不是单独索引网格的稳态内存。

| 模式 / 次序 | 总耗时 ms | OS 观测峰值字节 |
| --- | ---: | ---: |
| full 1 | 149.6 | 23982080 |
| full 2 | 45.8 | 23187456 |
| full 3 | 46.1 | 23187456 |
| convert 1 | 244.7 | 40390656 |
| convert 2 | 235.2 | 40394752 |
| convert 3 | 223.7 | 40390656 |

OS 高水位工作集/RSS 每 10 ms 采样，结果是观测下界，不能保证捕获完整峰值。耗时含整个子进程，第一次启动与缓存效应未剔除；单机小样本不支持普遍速度结论。

逻辑字段估算：原 Mesh 为 96×F=9,600,000 字节；索引表示为 24×V+36×F=4,810,824 字节（含逐面法线与 Int32 三索引）。这不是堆对象/容器/引用/哈希表/分配器大小，不能用该比例宣称实际内存减半。**实测转换峰值约 40 MB，高于 full 的约 23–24 MB。** 目前没有证据表明把旧流程直接加一次转换就能节约峰值内存。

复现：

```sh
# PYTHON 指向已有 Python3；Linux 默认 python3。
moon run scripts/indexed-memory.mbtx
```

生成源为 `tools/indexed_bench/main.mbt`，测量复用既有 `scripts/measure-process.py`。临时报告写入 `_build/indexed-memory/`。本记录不被 CI 自动覆盖；回归测试验证几何结果，不强制一个依赖机器的性能阈值。
