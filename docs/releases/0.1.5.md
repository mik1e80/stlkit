# 0.1.5 — 可靠性维护

后续更正：发布后核查发现独立 consumer 脚本未升级原有依赖，可能实际使用 0.1.4。修正后的脚本已断言安装版本并验证真实 0.1.5 的四后端调用；脚本修正由 [0.1.6](0.1.6.md) 交付，旧标签不移动。下文描述本版本的核心功能；不要用旧启动脚本的请求版本输出证明安装版本。

2026-10-28。此版本是后续路线的第一批交付，未加入 IndexedMesh、BVH、自相交或 JSON CLI。

- 新增 `ParseLimits`，对 STL / OBJ / PLY / 3MF 及 STL 扫描器统一传递限额，提前拒绝超大声明、长行、多边形、PLY 零属性记录和重复组件展开。
- 3MF 先核对 ZIP 元数据预算再解压，并开启 CRC；默认及兼容读取均执行资源限制。
- CLI 在分配整文件缓冲区前检查文件大小，提供四个资源选项；网页提供文件/面数限额。
- 修复合法 Binary STL 的 opaque header 恰好以 ZIP 或 PLY 魔数开头时被自动入口误路由的问题。
- 新增独立变异工作流、真实 CLI 限额回归、干净目录 Mooncakes consumer 安装/四后端调用；新增源代码和内存种子采用 Apache-2.0，无新第三方模型。

## 兼容与验证

旧的解析调用方式保留，默认引入有限预算。超限可能拒绝此前允许的大文件，显式传 `limits` 调整；详见 [资源预算](../resource-limits.md)。不放宽任何格式语法，不承诺进程内存/时间上限。历史 v0.1.4 标签及发布包不移动。

本地四后端各 371 项库测试；变异测试四后端各 1,000 和 10,000 次结果一致，详情及摘要见 [变异报告](../fuzz-testing.md)。67 次模型读取、5 次修复重载、10 次厚度对照、真实 CLI、网页和 100k 全量/分块一致性回归通过。外部模型完整来源、许可证与哈希检查通过。固定缺失 format 负向样例的 Git 字节保存规则，避免 Windows 导出换行影响原始哈希。历史更大规模性能数据保持原测量日期。

固定版本入口：`moon add mik1e80/stlkit@0.1.5`、GitHub `v0.1.5`。发布包 consumer 工作流随正式 Release 运行；它从全新目录安装指定包，不引用工作区源码。
